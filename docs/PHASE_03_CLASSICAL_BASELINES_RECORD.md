### One implementation correction, made before any metric existed

LightGBM 4.7.0's scikit-learn wrapper requires scikit-learn, which is not part
of the frozen V2 runtime. Rather than install a package after freezing, B3 was
implemented against LightGBM's **native Booster API** and the grid re-expressed
in native parameter spelling — `min_data_in_leaf`, `bagging_fraction`,
`feature_fraction`, `lambda_l1/l2`, `seed`, `num_threads`, and
`num_boost_round` passed to `lgb.train`.

The eight candidates and their values are unchanged; only the spelling is
native, which is what §11 of the protocol asks for. The correction was made
**before any validation metric was computed** — the first run failed at the
first fit — and the freeze records both spellings, the mapping between them,
and the reason. The freeze and the opening receipt were re-issued before
validation opened.

## 4. Frozen B3 contract

**Grid — exactly eight candidates**, generated by the documented nested loop
(`learning_rate ∈ {0.03, 0.07}` outer, `num_leaves ∈ {31, 63}`,
`min_child_samples ∈ {50, 200}` inner), giving B3_C01 … B3_C08. Fixed:
`num_boost_round = 400`, `max_depth = -1`, bagging and feature fractions 1.0,
`lambda_l1 = 0.0`, `lambda_l2 = 1.0`, `objective = regression_l1`,
`metric = l1`, **no early stopping** — an early-stopped iteration count would
be one more quantity chosen by looking at validation.

**Determinism**: `deterministic = true`, `force_col_wise = true`, all four
LightGBM seeds pinned to 42, no bagging or feature-subsampling randomness, and
`num_threads = 16` fixed identically across every candidate (20 logical cores
available; threads were never changed between candidates).

**Features**, frozen before validation: lags `0, 1, 2, 3, 6, 12, 24, 47` — no
lag 48, because it lies outside the canonical `[t−47, t]` window and admitting
it would require a hidden 49th hour. Trailing windows 3/6/12/24/48 h ending at
the origin with mean, std (population, ddof 0), min and max; no centred
statistic; no exponentially weighted feature. Observed mask at origin plus
observed fraction over 6/24/48 h for every numeric variable; gap age at origin
for every pollutant in the regime; `rain_occurred` at origin and its trailing
means; deterministic 17-way wind one-hot (16 frozen training categories +
MISSING); deterministic 12-way station one-hot; frozen origin and target cyclic
calendar. `day_of_week` and `weekend` excluded. Horizon is not a column because
models are trained per horizon.

Feature counts: **R0 = 207, R1 = 240, R2 = 405**. Twelve models were selected —
three regimes × four horizons. **R3 was not implemented**; it belongs to the
spatiotemporal phase.

**Selection**: macro-station validation MAE at that horizon — MAE per station,
averaged with equal weight over the 12 stations — with the frozen tie-break
order (macro MAE, macro RMSE, smaller `num_leaves`, larger
`min_child_samples`, lower candidate id) and a 1e-12 comparison tolerance.
Micro MAE was never used for selection.

## 5. Rolling-origin safety

Validation PM2.5 history reaches feature code only through
`src/data/rolling_history.py`, whose series is built by forward fill alone —
so the value at any index depends on observations at or before it — and whose
every accessor asserts that the window ends exactly at the requested forecast
origin. The unseal ceiling was set to the end of validation, so **test values
were never read off disk at all**.

The protocol permits either a strictly sequential walk or an equivalent
guarded index lookup, provided the equivalence is proven. It is:
`tests/test_rolling_history.py` re-derives the causal fill from
`CausalTargetHistory` at four separate origins and requires exact agreement
(`atol = 0, rtol = 0`) with the precomputed lookup, and separately asserts that
the training region of the rolling series is byte-identical to the Phase-2
canonical array.

Scoring is deliberately separated: `src/evaluation/scoring.py` is the only
place a validation target is read as evaluation truth, it refuses any timestamp
outside the validation window, and it requires the caller to present
already-produced predictions. In the run, all B0/B1/B2 predictions existed
before the oracle was instantiated.

## 6. What was found

The headline results are in
[`CLASSICAL_BASELINE_RESULTS.md`](CLASSICAL_BASELINE_RESULTS.md). Three
findings deserve recording here as facts of the phase rather than as
commentary:

1. **B3_R2 is best overall (30.112) but persistence is third (33.128) and beats
   the meteorology-only boosted model (40.623).** Almost everything B3 gains
   over persistence comes from PM2.5's own history.
2. **Persistence wins the severe tail outright** (101.27 against B3_R2's
   136.61), and every boosted model under-predicts severe hours more often than
   persistence does. The failure mode V1 documented survives into V2.
3. **B1 is identical to B0 at h = 24 in 100.00% of samples**, exactly as the
   arithmetic requires. It is reported as a collapse, not as an independent
   baseline at that horizon.

## 6a. A correction to the upstream validators

Running `validate_phase3.py` exposed a defect in the Phase-0, Phase-1 and
Phase-2 validators. Each contained a gate asserting that **no** model-result,
prediction or metric artifact exists anywhere in `artifacts/`, `results/` and
`figures/`, and Phase-1 and Phase-2 additionally asserted that no modelling
library is imported anywhere under `src/` and `scripts/`.

Those assertions were correct when written, but they were scoped to the whole
repository rather than to the outputs each phase owns. Phase 3 legitimately
produces exactly such artifacts — prediction arrays, candidate metric tables —
and legitimately imports LightGBM, so all three upstream validators began
failing on entirely correct work.

The gates were scoped to their own phase: paths under `results/validation/`,
`results/models/`, `artifacts/phase3_*`, the Phase-3 manifest and receipt, and
`figures/validation_*` are excluded, as are the Phase-3 scripts and
`src/models/b3_*` in the import scan. **The scientific assertion is unchanged**
— Phases 0, 1 and 2 still contain no model output — and the fix simply stops
those phases from claiming the repository must never contain one.

No recorded hash was affected: no manifest hashes any script, which the four
passing validators confirm. Nothing scientific changed.

## 8. Selection-optimism caveat

Eight candidates were scored on validation and the best retained, independently
in each of twelve cells. The reported selected values are therefore optimistic
estimates of held-out performance. V1 measured this effect directly — the
models that used validation to choose hyperparameters got slightly worse on the
locked test while those that chose nothing got slightly better — and the same
correction should be expected here. Only the locked test can settle it.

## 9. Pre-test discipline

Phase 3 is development only. The selected B3 models will **not** be refit on
validation. The test is not opened. Later phases add neural temporal models,
TSFMs, spatiotemporal models and robustness work; a new pre-test freeze is
created only after all development is complete.
